# 2026-09-07 — автосинхронизация ответвления winget (beads-web-pwm)

`wingetcreate` заливает манифест в ответвление `weselow/winget-pkgs` и оттуда
открывает заявку в каталог. Между выпусками ответвление устаревает — на v0.12.3
оно отставало на 22995 коммитов, и задание упало с `The forked repository could
not be synced with the upstream commits`. В задание winget в `release.yml`
добавлен шаг `gh repo sync` перед `wingetcreate`. `gh` уже стоит на сборочных
машинах GitHub, новых секретов не нужно: `WINGET_TOKEN` с областью `public_repo`
даёт право писать в собственное публичное ответвление.

**Почему шаг некритичный.** Сбой синхронизации только пишет предупреждение и не
роняет задание. Причин две: при самой первой отправке ответвления ещё нет, его
создаёт сам `wingetcreate`; и во-вторых, к моменту запуска winget выпуск на
GitHub, Scoop и Homebrew уже опубликован — терять его из-за проблемы с
синхронизацией бессмысленно. Худший исход равен прежнему поведению, а ручное
лечение записано в `RELEASE.md`.

**Тонкость PowerShell, из-за которой это не одна строка.** GitHub запускает шаг
с `$ErrorActionPreference = 'stop'`, а в PowerShell 7.4+ при этой настройке
внешняя команда с ненулевым кодом возбуждает прерывающую ошибку (за это отвечает
`$PSNativeCommandUseErrorActionPreference`, и её значение по умолчанию менялось
между версиями). Поэтому вокруг вызова настройка временно переключается на
`Continue`, код возврата проверяется вручную, а `$LASTEXITCODE` сбрасывается в
ноль — иначе неудачная синхронизация утекла бы в код возврата всего шага, ведь
GitHub дописывает в конец `exit $LASTEXITCODE`.

**Как проверяли без выката.** Тело шага вынуто из YAML, шаблоны `${{ }}`
подставлены, вызовы `gh` и `wingetcreate` заменены заглушками с нужным кодом
возврата, сверху и снизу добавлена та же обёртка, которой GitHub оборачивает шаг
на `pwsh`. Прогнаны пять сочетаний: обе команды успешны, упала только
синхронизация, упала только отправка, упали обе, и токена нет вовсе. Ожидаемый
код возврата шага получился во всех пяти. Ключевой случай — синхронизация упала,
отправка прошла — даёт ноль, то есть выкат остаётся зелёным.

**Что проверить, если сломается.** Смотреть на предупреждение `::warning::Could
not sync` в журнале задания. Если оно есть и следом идёт прежняя ошибка про
несинхронизированное ответвление — значит `WINGET_TOKEN` не даёт прав на запись
в ответвление или его имя не `<owner>/winget-pkgs`. Имя берётся из
`github.repository_owner`, а не зашито.

**Что намеренно не трогали.** Принудительную синхронизацию (`--force`) не
ставили: она молча выбрасывает коммиты, которые могли бы оказаться в
ответвлении. Сейчас своих коммитов там нет — `wingetcreate` шлёт отдельную ветку
и `master` не трогает.
