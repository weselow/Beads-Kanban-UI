# 2026-09-07 — панель агентов и настоящие значения полей tools/model (beads-web-rgp)

Из сообщения об ошибке №42 на GitHub: панель агентов гасла у всех, у кого файлы
`.claude/agents/*.md` написаны обычным для Claude Code способом. Три разных
падения, все с одной причиной — договорённость между сервером и интерфейсом была
описана уже, чем бывает на самом деле.

**Что чинили.**

1. `server/src/routes/agents.rs`: у перечисления `AgentTools` стояла пометка
   `#[serde(untagged)]`, а вариант `All(String)` шёл первым. Serde пробует
   варианты по порядку, поэтому *любая* строка попадала в `All`. Запись
   `tools: Read, Grep, Glob, Bash` доезжала до браузера сырой строкой, а
   `formatToolsSummary` звал у неё `.join` — которого у строки нет.
2. Поле `model` — свободная строка на сервере, но на стороне интерфейса тип был
   объявлен как `'opus' | 'sonnet' | 'haiku'`. Значения `inherit`, `opusplan`,
   полный идентификатор модели и пустая строка (поля нет вовсе) давали
   `MODEL_COLORS[model] === undefined`, и обращение к `colors.bg` роняло панель.
3. Если `tools:` в файле нет совсем — а это самый частый случай, он означает
   «все инструменты» — сервер слал `null`, а тип на клиенте требовал значение
   обязательно.

**Почему именно так.**

- Приведение значений к нужному виду сделано **на сервере**, а не на клиенте.
  Для `AgentTools` написана своя разборка (`impl Deserialize`): скаляр `*`
  остаётся признаком «все инструменты», любой другой скаляр режется по запятым в
  список, список остаётся списком, пустые куски выбрасываются. Так интерфейс
  получает ровно две формы вместо трёх: строку `"*"` либо массив. Клиентские
  подстраховки оставлены, но это второй рубеж, а не основная починка.
- Разбор скаляра стоит в `Deserialize`, а не в `parse_agent_file`, чтобы
  приведение работало на всех путях сразу: и при чтении файла, и при повторном
  чтении после записи в обработчике `update_agent`.
- `model` намеренно оставлена свободной строкой и на сервере, и в типах. Отбирать
  «неизвестные» значения нельзя: `inherit` и `opusplan` — законные записи, а
  переключение «все инструменты» обязано сохранить текущее значение модели
  нетронутым. Из-за этого пришлось расширить тип у `updateAgent` и
  `api.agents.update` с `AgentModel` до `string`.
- В панели незнакомая модель получает нейтральный цвет
  (`UNKNOWN_MODEL_COLORS`), пустая — подпись `default`. Переключатель моделей
  при незнакомом значении просто не показывает выбранным ни один из трёх
  вариантов — так и задумано, это честнее, чем подсветить случайный.

**Что смотреть первым, если сломается.**

- Панель снова пуста и в консоли `Cannot read properties of undefined` — значит
  появилось ещё одно поле, чей тип на клиенте уже реальности. Смотреть
  `src/types/index.ts`, раздел Agent Types, и сверять с `AgentInfo` в
  `server/src/routes/agents.rs`.
- Инструменты показываются как «No tools» там, где их ожидали, — проверить
  `normalize_tools_scalar` в `agents.rs`: скорее всего в файле агента разделитель
  не запятая.
- Проверки: `cargo test --locked routes::agents` в папке `server/` и
  `npx vitest run src/components/__tests__/agents-panel.test.tsx`.

**Что намеренно не трогали.**

- Переключатель «All tools» умеет только включаться. Обработчик `update_agent`
  вписывает `tools: '*'` при `all_tools: true`, но при `false` не делает ничего,
  поэтому обратно выключить не получается. Это отдельная поломка, не из этого
  сообщения об ошибке, — в задачу не входила.
- Раздел «Tools (N)» в раскрытой карточке рисуется только для массива. Если с
  устаревшего сервера придёт строка с запятыми, список не покажется, но краткая
  строка сверху всё равно перечислит инструменты — падения нет.
- Проверка значения `model` на стороне сервера не добавлялась: набор допустимых
  имён моделей меняется у Anthropic, и жёсткий список устареет быстрее кода.

## Переключатель «все инструменты» стал односторонней кнопкой

Найдено при работе над задачей #42: переключатель «All tools» умел только
включаться. `update_agent` (`server/src/routes/agents.rs`) при `all_tools: true`
вписывает в файл агента `tools: '*'`, а при `false` не делает с полем ничего —
вернуть прежний список было нельзя, он к тому моменту уже затёрт звёздочкой.

Из четырёх разобранных вариантов выбран самый честный: действие сделано
односторонним. Вместо переключателя — кнопка «Grant all tools», неактивная с
подписью «Already has all tools», если у агента уже стоит звёздочка. Причина:
панель не умеет выбирать отдельные инструменты, поэтому обещать возврат к
прежнему набору она не может. Стирать поле `tools` при выключении тоже не
годится — в Claude Code отсутствие поля означает «наследовать все инструменты»,
то есть оба положения переключателя давали бы агенту одно и то же, а человек
видел бы выбор, которого нет.

Серверная ветка `if payload.all_tools` осталась как была, но теперь это
осознанное поведение — рядом лежит объясняющий комментарий.

**Что проверить, если сломается.** Смена модели у агента с ограниченным списком
инструментов не должна затирать список: `handleUpdateModel` шлёт
`all_tools: false`, и сервер обязан оставить поле нетронутым. Тест на это —
«keeps the tool list when only the model changes».

**Что намеренно не трогали.** Выбор отдельных инструментов в панели — это новая
возможность, а не починка; в 0.12.4 не входит.
